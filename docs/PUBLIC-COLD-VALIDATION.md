# Three-channel public dependency cold bootstrap

The portable driver `scripts/verify-public-cold-install.mjs CHANNEL ARTIFACT_DIR NEW_ROOT` uses only a dedicated verified artifact directory and public npm mirror dependencies. CHANNEL is rc6, rc2 or alpha5. No private node_modules ancestor or symlink is used. `public-dsh-family.json` freezes each exact DSH package-name set, including CLI; every family member is a direct exact dependency with matching override. A final lock check rejects another DSH version or an unknown family member. Non-optional public peers are completed in at most five rounds. cordis-plugin-group is explicitly 1.0.2. This avoids the observed upstream caret drift from rc6 to rc7/rc8 and nested missing group peer.

Use Linux x86_64, Node 24 and preverified main/host/platform plus runtime tgz files. npm lifecycle scripts remain disabled. Default per-root node_modules ceiling is 400 MiB; DSH_COLD_MAX_KIB can set an explicit finite limit up to 800 MiB. DSH_COLD_NPM_CACHE optionally reuses a caller-selected download cache; it does not reuse installed packages. HOME and DSH_HOME are always private. Logs, package lock and summary.json stay in NEW_ROOT. Inspect failure logs before using the explicit `--resume-fixture` fourth argument, which accepts only this driver's named fixture and matching DSH version. It is not a production profile updater.

Old rc6 needs a special, visible prerequisite: node-pty 1.1.0 has no Linux prebuilt module. A make/C++/Python toolchain and matching Node headers must be supplied. After reviewing that package's scripts, explicitly rebuild only node-pty inside the fixture, for example `npm rebuild node-pty --offline --ignore-scripts=false --nodedir="$NODE_HEADERS"`, then resume the fixture. The driver never automatically enables every package's lifecycle scripts, installs a compiler globally, or rebuilds the approval bridge. Our remote check used original public Node24 headers and a checksum-verified Ubuntu make package extracted into a temporary tool directory, one compilation job. rc6 also does not support --no-open; the driver follows that CLI's actual web help.

Observed on 2026-09-03: rc6 plugin0.5.5-rc.2 / DSH0.1.0-rc.6, rc2 plugin0.5.6-rc.2 / DSH0.1.1-rc.2, and alpha5 plugin0.5.7-alpha.2 / DSH0.1.2-alpha.5 all completed --help, --dump-config and real loopback HTTP bootstrap. All six AutoReview fibers reached ACTIVE (state2), and actionReview/actionReviewSettings/settings/agents/tools/sandboxPolicy/commands were present. Each controlled server exited0. The final rc6 and alpha5 dependency trees together used approximately737 MiB. They began as fresh public installations but were repaired in-place after retained failures; this is not an assertion that the first unmodified attempt succeeded. The final frozen-family generator has syntax validation; a second untouched fresh-root repetition of its exact final source has not yet been performed.

Alpha5's native authentication was retained: anonymous root returned401, the normal process launch-token exchange returned303, and its authority-bound cookie returned200. The driver follows only same-origin redirects and redacts launch URL queries in persisted stdout; no token is printed in the report. Earlier401 was a test-client omission, not a reason to disable the authentication fence.

This is backend cold bootstrap and static HTML availability, not browser-use evidence or a full user installation certification. No hot host patches, native approval requests, model calls, credential setup or coding task were exercised. Protected native runtime provisioning and the existing incomplete Guardian/production gates remain separate. Prior rc2 browser evidence does not cover rc6 or alpha5. Each report preserves these NOT_EXERCISED fields. The historical SOURCE matrix remains separately reproducible with check-compat-channel.mjs and does not convert skipped UI tests into passes.
